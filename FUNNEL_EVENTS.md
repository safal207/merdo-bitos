# Merdo × BitOS — event contract v1 (session diagnostic)

Этот документ описывает **локальную диагностику**, а не аналитический сервис. На GitHub Pages нет backend, профилей, CRM, сбора посетителей, cookies или автоматически отправляемых событий. Поэтому статистика отражает **только действия одной вкладки браузера**. Её нельзя использовать для выводов о продажах, числе покупателей, выручке, CVR по магазину, CAC, ROAS, ARPU или LTV.

## Назначение

Проверить, что интерфейс Grok и демонстрационная воронка ClickFunnels формируют правильные события на каждом этапе, прежде чем согласовывать реальную аналитику с Merdo.

Схема записи:

```json
{"event":"look_viewed","time":1795000000000}
```

Один event name из allowlist и время Unix ms. **Никаких параметров:** gender, occasion, budget, products, size, SKU, URL, UTM, email, phone, name, photo, content of draft or free text. Последние 150 событий в `sessionStorage["bitos:session-analytics:v1"]`, удаляются по кнопке, при закрытии вкладки или браузера в зависимости от политики браузера. Если `sessionStorage` запрещён, журнал доступен только в памяти открытой страницы. Отправки на сервер нет.

## События

| Event | Когда формируется | Что нельзя утверждать |
| --- | --- | --- |
| `session_opened` | Первый рендер в данной вкладке с пустым журналом | Это **не** уникальный посетитель |
| `stylist_started` | Начало 4-шагового квиза | Не лид |
| `step_1_completed` ... `step_4_completed` | Переход с текущего шага вперёд | Не реальные консультации |
| `look_viewed` | Результат после шага 4 | Не примерка и не покупка |
| `look_details_opened` | Раскрыты подробности образа | Не товарный просмотр SKU |
| `stylist_copy_attempted`, `stylist_copy_succeeded` | Попытка/успешный ответ Clipboard API | Копирование **не означает**, что клиент отправил заявку |
| `funnel_started` | Открыта демо-воронка Tripwire | Не переход в кассу |
| `tripwire_interest` | Выбрана идея недорогого аксессуара | Не оплата |
| `core_stage_viewed` | Показана смета основного комплекта | Не подтверждение наличия |
| `bump_stage_viewed`, `bump_interest` | Показан портной / выбрана дополнительная услуга | Не оказание услуги |
| `oto_stage_viewed`, `oto_interest` | Показан гипотетический post-purchase OTO / интерес ко второму образу | **Никакой покупки не произошло** |
| `retention_stage_viewed`, `funnel_demo_completed` | Виден заключительный демонстрационный экран | Не возврат клиента |
| `funnel_copy_attempted`, `funnel_copy_succeeded` | Попытка/успех копирования итогового текста | Не CRM-заявка |

В коде **нет и не должно быть** событий `purchase_completed`, `payment_success`, `appointment_booked`, `lead_submitted` до подключения соответствующих подтверждённых процессов.

## Контрольные вехи в панели

Панель «Диагностика воронки» закрыта по умолчанию и доступна из нижней части главной страницы. Показывает 9 локальных контрольных вех: начало сеанса, старт квиза, показ образа, старт воронки, core, order bump, OTO, retention, завершение демонстрации. Отображает историю последних 12 событий, число локальных событий и 9 булевых вех. **Это не конверсионная воронка по людям**. Счётчик может содержать повторные события от одного посетителя.

Кнопки **Скопировать JSON событий** (с альтернативой ручного выделения) и **Очистить журнал** работают без сети. Рендер панели RU/TR.

## Что понадобится для реальной аналитики

1. Подтвердить отношения с магазином, правовые основания обработки и политику согласий (в т.ч. аудит cookies и внешних шрифтов).
2. Определить first-party измерение на стороне сервера или разрешённый аналитический инструмент, безопасный ingestion и лимиты хранения; сбор только после согласия там, где это требуется.
3. Разделять `look_viewed` и реальные конверсии `appointment_confirmed`, `sale_paid`, `sale_refunded`, `tailoring_paid`; реальные факты подтверждаются POS/CRM/backend.
4. По согласованным данным определить деноминаторы (сессии и покупатели — разные сущности), метрики `view→quiz`, `quiz→request`, `request→fitting`, `fitting→sale`, средний чек, возвраты и прибыль.
5. Настроить QA по источникам и событиям: дубляжи, пропущенные события, idempotency, attribution, отложенные оплаты/возвраты и безопасность клиентских данных.
