# Merdo × BitOS — Fashion Stylist (Grok design)

**Независимый концепт для Merdo. Не официальный сайт и не каталог магазина.**

Главная страница `/index.html` перенесена на основу визуального дизайна Grok из пользовательского `grok-workspace.zip`. Это **статическая адаптация** (HTML/CSS/JavaScript) для GitHub Pages, а не прямой деплой серверного TanStack Start-приложения.

## Что показывает новый сайт

- Фотореалистичные кадры **из исходного архива Grok**, все 8 фотографий сохранены в `/looks/` в оригинальном разрешении: мужчина/женщина × formal/partners/creative/casual;
- 4 шага: повод/пол → посадка, крой брюк, обувь → бюджет → портной и собственные категории вещей;
- подсчёт долей по оригинальным правилам Grok: при покупке обуви **38 / 19 / 14 / 23 / 4%**, иначе **44 / 23 / 20 / 0 / 8%**;
- вещи «уже есть» → 0 к покупке, деньги не перераспределяются; **портной 400/650/500 ₺ отдельно**;
- после 4-го шага **фотография модели сразу на экране**, ниже состав, суммы и копируемый запрос без отправки;
- RU/TR, безопасное восстановление из `localStorage`, адаптивность от 390 px, отсутствие обязательного аккаунта.

**Проверочный пример:** женщина, creative, свободная посадка, свободные брюки, обувь есть, бюджет 15 000 ₺, подшив брюк 400 ₺, свой тёмно-синий жакет → **7 650 ₺ к докупке, 7 350 ₺ резерв, портной 400 ₺ отдельно**.

Цвет собственной вещи меняет метку/расчёт, **не перекрашивает фотографию**. Посадка и крой брюк влияют на текст для примерки, а не на пиксели. Кадры показывают разных моделей, не виртуальную примерку. Ни один кадр не является фотографией подтверждённого товара Merdo.

## Перенос в Grok из прежней витрины

На `legacy.html` у разделов «Мой гардероб» и «Тестовые товары» добавлены кнопки перехода в главный стилист. В пределах одной вкладки пакет передаётся через `sessionStorage` и удаляется при чтении; время жизни 10 минут. Из гардероба передаются только отмеченные категории, цвет и фасон — без личных фотографий. Из тестовых карточек — имена, демо-коды, размеры, пол и условная сумма, которая задаёт стартовый бюджет. Демо-карточки не становятся реальными SKU и не считаются вещами покупателя. Источник и условная сумма показываются отдельно; русский и турецкий языки сохраняются. Маршруты тестируются в `scripts/bridge-smoke.mjs` на 390 и 1280 px.

## Предыдущая версия сохранена

Вся исходная витрина с фотолентой, лайками, подробным гардеробом (включая пользовательские фотографии), тестовыми карточками и проверкой каталога доступна как **[legacy.html](./legacy.html)**. Из новой версии есть вторичная навигация «Другие инструменты BitOS» внизу страницы.

Гардероб v1 (ключи `bitos:wardrobe:v1`/`v2`) импортируется в новый стилист **только по категориям и выбранным цветам** при первом открытии без сохранённого нового состояния. Фото пользователя не копируются, не отправляются на сервер и не вкладываются в запрос.

## Проверки и выпуск

`.github/workflows/pages.yml` выполняет:
1. проверку синтаксиса нового скрипта;
2. **Grok acceptance** на 390 и 1280 px: оригинальное фото загружается, полный путь покупателя, точная смета, сохранение, RU/TR, черновик и отсутствие горизонтальной прокрутки;
3. всю прежнюю `scripts/smoke.mjs` на `legacy.html`;
4. `scripts/ux-audit.mjs` на `legacy.html` в Chromium, Firefox, WebKit.

Публикация GitHub Pages разрешена только после зелёных проверок `main`. Для новой версии не требуется серверная база, логин или переменные окружения Grok.

## ClickFunnels / SamCart: демонстрационная воронка

После просмотра полного образа на главной странице есть **«Показать воронку продаж»**. Визуальный сценарий в `sales-funnel.js` и `sales-funnel.css` показывает, как бесплатно подобранный образ (lead magnet) может привести к маленькой первой покупке (гипотеза Tripwire), полному комплекту (core offer), опциональной услуге портного (order bump), предложению **после будущей подтверждённой покупки** (OTO) и добровольному повторному обращению (retention). RU/TR.

- **Это только прототип сценария:** нет реальных SKU, оплаты, бронирования, скидок, искусственной срочности, сбора персональных данных, SMS/email, CRM или сетевой аналитики. Нажатия не означают совершённой покупки.
- Сумма одежды и резерв из стилиста не меняются от гипотетических предложений. Дополнительная услуга портного идёт отдельно; уже выбранные в анкете услуги не могут начисляться повторно.
- Вместо оформления заказа — **копируемый текст запроса** с дополнительными вопросами, не отправляемый никуда автоматически. Сценарий работает в текущей вкладке.
- Переходы этапов, портной без двойной оплаты и корректные условные суммы проверяются `scripts/grok-smoke.mjs` на 390 и 1280 px.
- Реальные Tripwire, платёж, OTO и расчёт окупаемости остаются в [Issue #8](https://github.com/safal207/merdo-bitos/issues/8) до согласования ассортимента, процессов и юридических условий магазина.

## Диагностика пути покупателя — локальная аналитика

Новая панель **«Диагностика воронки»** расположена внизу страницы, по умолчанию свёрнута. Она фиксирует локальные события этой вкладки: старт стилиста, завершение четырёх шагов, показ образа, открытие предложений Tripwire, core, Perfect Fit, OTO, retention, а также попытку и факт успешного копирования черновика.

- Локальный журнал содержит **только названия событий и время**, максимум 150 записей в `sessionStorage`; нет cookies, ID пользователя, URL/UTM, пола, цены, содержимого запроса, фото или внешней отправки.
- В панели можно проверить 9 вех, скопировать JSON либо очистить историю. Сохранение работает при обновлении вкладки; при блокировке хранилища используется память страницы.
- **Это не аналитика посетителей магазина:** события одной вкладки не отражают число пользователей, долю конверсий и реальные продажи. Гипотетический OTO и копирование черновика не означают покупку или отправку заявки.
- Термины, триггеры событий и будущие требования к интеграции описаны в [FUNNEL_EVENTS.md](./FUNNEL_EVENTS.md); см. [Issue #14](https://github.com/safal207/merdo-bitos/issues/14).

## Принцип прозрачности

- **Подтверждённых SKU Merdo: 0** в BitOS; наличие реального магазина не означает открытый каталог.
- Условные цифры в ₺ служат для демонстрации бюджетирования, не для оформления заказов или финансового предложения.
- Никаких фальшивых скидок, ограниченности по времени, оплаченных заказов и заявок.
- Партнёрство, разрешения на товарные фото и работа ателье требуют подтверждения владельца.
