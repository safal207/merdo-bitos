# Opportunity Window Engine 9.0 — experimental
Baseline: Trust & Communication 8.9, 36380e9. Inspired by Jeff Walker, Launch / Product Launch Formula (author site https://jeffwalker.com/ and https://productlaunchformula.com/); preparation, opportunity, transformation, ownership, launch and post-launch. This is a BitOS design interpretation, not a claim of reading the full book or proof of sales lift.

Two clocks: phase of client context relative to an explicitly provided anchor; independently configured business calendar. Strictly increasing boundaries, half-open intervals: [prepare, opportunity), [opportunity, transformation), [transformation, ownership), [ownership, open), [open, close), [close, infinity). No real production deadlines inferred. Days use one explicit synthetic calendar; production timezone/date handling is outside this experiment.

The engine is a pure read-only adapter over Customer Need Graph, Need Activation and Trust session summary. It distinguishes phase matching, confirmed stated need, compatible offer, current synthetic activation snapshot, verified availability, deadline feasibility, and explicit discussion request. Missing or stale verification is unknown, never feasible. Verification is a supplied synthetic fixture; no external inventory verification or reservation. Lead days include all required production/fitting buffers in the supplied fixture. Deadline equality is feasible; use subtraction to avoid overflow. Availability verification includes offer, source, checked day and inclusive expiry. No artificial scarcity: launch closure denotes an experiment calendar, not a claim of inventory shortage.

Learning outcome is descriptive, not a requirement to take a course or a proxy for consent. Independent understanding can be unknown while a person explicitly requests a discussion. No purchase, payment, CRM, messages or LTV effects. Decline or stop cannot authorize a discussion. The output aligned is a theoretical intersection, not actual purchase intent; canDiscuss requires explicit request and consent. No automatic outreach. Before launch the calendar describes content planning only, not forced exposure. Hypotheses need real assortment, lead time, context and owner validation before any client UI integration.

Tests cover strict calendar boundaries, time/space mismatch, stale activation, missing/future/expired availability, deadlines, integer bounds, consent and decision, read-only replay and no side effects. Run node scripts/atelier23-opportunity-window.mjs.
