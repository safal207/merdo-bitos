# BitOS 8.7 — Pedagogical Foundations
Status: design hypothesis / documentation only. Baseline 8.6: 8ac19332b8ead0de8c91bd08b764910f828cb6af. Источники: PEDAGOGICAL-SOURCES.md. Протокол проверки: PEDAGOGICAL-VALIDATION.md.

## Решение
Разделить развитие потребности и обучение; человек не воронка. Потребность не обязана быть циклической, а повторение может относиться к одному человеку или к популяции. Переходная фаза, мотив, действие, результат, опыт и бизнес-цель — отдельные сущности. Не моделируем скрытый психологический профиль человека. Научные теории — основания проектных гипотез, не доказательство маркетингового эффекта.

## Слои
| Слой | Вход и выход | Запрет |
|---|---|---|
| Transition / Need Graph 8.5 | Сообщённый контекст и фаза -> возможные потребности / предложения | Не выводить факт потребности из совпадения контекста |
| Activation 8.6 | Синтетические события -> условная интенсивность | Не использовать интенсивность как реальное психологическое измерение |
| Motive Discovery | Слова человека, необязательный выбор -> заявленный мотив / unknown | Не присваивать скрытые мотивы |
| Learning | Задача, помощь, попытка -> наблюдаемое выполнение с уровнем поддержки | Не считать просмотры или правильный ответ с подсказкой самостоятельным освоением |
| Experience | Явная обратная связь о результате -> helpful / mixed / unhelpful / unknown | Не считать оплату удовлетворением |
| Development | Новое добровольное описание потребности -> возможное изменение прежней модели | Не считать человека развившимся по одному клику |
| Decision / Economics | Отдельное решение клиента и учёт оплаченных заказов -> метрики | Не превращать обучение или удовлетворение в платёж; не прогнозировать LTV без данных |

## Состояние (проект контракта)
Session = { topicId, context: unknown|self_reported, motive: unknown|self_reported, understanding: unknown|oriented|assisted|independent|transfer_demonstrated, support: none|hint|example|guided, readiness: unknown|explore|defer|decline|request_discussion, experience: unknown|helpful|mixed|unhelpful, active: true|false, evidenceRefs: [], revision, eventIds: [] }.
Understanding относится только к конкретной задаче и текущей версии материала. Это наблюдаемый результат, не интеллект и не стадия личности. Состояние unknown допустимо всегда. Отказ не ошибка. Независимые координаты: условная интенсивность I (8.6), наблюдаемое понимание U, явно заявленная готовность R. Нет функции I -> U -> R.

## Переходы
| Событие | Предусловие | Изменение |
|---|---|---|
| orient | пользователь выбрал задачу | oriented, если ознакомление подтверждено; не готовность |
| request_hint | активная сессия | выбранная помощь, без повышения U |
| attempt_with_help | проверяемый результат, помощь использована | assisted при успехе; иначе сохраняем наблюдение ошибки и предлагаем помощь |
| independent_attempt | проверяемый результат, без подсказок к этой попытке, новый вариант задачи | independent при успехе |
| transfer_attempt | independent, новый неповторяющийся контекст, заранее определённая рубрика | transfer_demonstrated при успехе |
| clarify_or_retry | изменились условия / обнаружена ошибка | допускает возврат к oriented или unknown |
| reflect | явная обратная связь | experience; не меняет оплату и готовность |
| report_need_change | явное новое описание человека | обновление гипотезы; не автоматическое усиление потребности |
| choose_next | явный выбор | readiness только; request_discussion не заказ |
| stop / reset | всегда | прекращение / сброс текущей сессии; нет автоперехода к пилоту |

После stop никакая помощь не инициируется автоматически; новую сессию человек запускает сам. Смена темы инвалидирует связанные результаты, подсказки и черновик; историю сессии не сохраняем по умолчанию. События идемпотентны по ID и содержимому; конфликт ID отклоняется, неверный порядок не меняет состояние. Не отправлять уведомления, не создавать записи CRM, не запрашивать чувствительную информацию. Никаких скрытых «баллов продаж».

## Два самостоятельных сценария
A. Андрей (B2B): выбрать актуальную задачу -> увидеть скриншот и факт -> самостоятельно повторить тест -> отличить дефект от неизмеренного ущерба -> по желанию проверить другой сценарий -> выбрать проверку/отложить/обсудить. Пример переноса: понимает, что наличие UTM не доказывает продажу. Нет теста на согласие с продавцом.
B. Покупатель Atelier 23 (B2C, будущий эксперимент): выбрать ситуацию -> сравнить посадку/ткани/условия использования -> при желании запросить помощь -> применить критерий к другому образу -> дать обратную связь. Любой этап можно пропустить, нет обязательной покупки. Наличие услуг и ассортимент требуют проверки.
Оба сценария отделены; результаты понимания владельца не переносятся на его покупателей.

## QA-контракт для следующей реализации
P0: отсутствие повышения U по просмотру/покупке; assisted не independent; transfer только новый сценарий; отказ и сброс не приводят к продаже; неизвестный мотив не угадывается; повтор события не повышает показатели; помощь не меняет I; U не меняет R; платежи и LTV не создаются обучением. P1: повтор задачи, изменение темы, возврат назад, доступность, короткие объяснения, отказ без ущерба.
В этой миссии только документация, новых runtime-модулей и тестов нет.
