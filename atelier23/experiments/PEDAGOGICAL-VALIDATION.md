# BitOS 8.7 — Матрица научных принципов и проверяемых гипотез
Все H — предварительные продуктовые гипотезы. Критерии ниже проектные, не опубликованные эффекты исследований. Сначала короткий качественный тест, затем при достаточном трафике рандомизированное сравнение. Источники S1–S7: PEDAGOGICAL-SOURCES.md.

| ID / источник | Принцип | Интервенция vs контроль | Основной наблюдаемый результат | Что опровергнет гипотезу / риск |
|---|---|---|---|---|
| H1 / S1 | Потребность, мотив, действие различны | Сначала открытая потребность и уточнение мотива vs выбор товара | Доля участников, подтвердивших своими словами соответствие рекомендации задаче | Не лучше контроля или выше доля неверных рекомендаций |
| H2 / S2 | Контекст меняет задачу | Добровольный выбор переходной ситуации vs общий список | Релевантность вариантов по независимой рубрике и оценке участника | Контекст не улучшает релевантность или ведёт к ложным выводам |
| H3 / S3 | Освоение через действие | Доказательство + самостоятельный повтор vs чтение отчёта | Правильное самостоятельное различение факта и гипотезы на новой задаче | Только узнавание ответа с подсказкой, без самостоятельного улучшения |
| H4 / S4 | Общий способ и перенос | Объяснить критерий, применить к другому примеру vs список готовых решений | Доля успешных новых задач без подсказки | Улучшение только на повторённом примере |
| H5 / S5 | Адаптивная помощь | Подсказка по запросу/ошибке с уменьшением помощи vs фиксированная инструкция | Самостоятельное выполнение; вторично число подсказок | Сохраняется зависимость от подсказок или растёт фрустрация |
| H6 / S6 | Качество опыта и последующий опыт | Необязательное практическое действие и рефлексия vs пассивное описание | Польза по самоотчёту и удержание понимания через 7 дней при согласии | Нет улучшения, отрицательный опыт или избыточное время |
| H7 / S7 | Автономность взрослого | Выбор пути, глубины и выхода vs линейный диалог с тем же правом выхода | Оценка контроля над решением; понимание как вторичный показатель | Рост ощущения давления, снижение понимания, отсутствие преимущества |

## Протокол
1. B2B и B2C исследовать отдельно. Для первого пилота 5–8 добровольцев на сценарий — выявление проблем, не статистическое подтверждение. У Андрея нет «правильного» коммерческого выбора; интервью не предполагает продажу.
2. Перед тестом зафиксировать задачу, рубрику (например, отличает факт от причинного утверждения, 0/1 по каждому заранее заданному критерию), время, варианты и порог практической значимости. Не использовать вариант с худшими правами отказа. Проверяющий по возможности не знает группу. Для количественного этапа рассчитать объём по базовой частоте и минимально значимому эффекту; рандомизировать на уровне участника, учитывать пропуски, доверительные интервалы и множественные сравнения. Не выбирать победителя по случайному всплеску.
3. Один пример в обучении, другой в проверке; правильный ответ не показывать перед контрольной попыткой. Помощь разрешена в обучении; маркировать её отдельно. Одинаковые доказательства и факты в группах. Время и число подсказок — дополнительные показатели, а не цели сами по себе.
4. Guardrails: добровольность, возможность пропустить/остановить, отсутствие ухудшения точности фактов, понятность, доступность, отсутствие давления; любое нарушение добровольности — stop. Отсутствие ответа = unknown, не ноль понимания.
5. Метрики: доля самостоятельных правильных ответов = успехи / участники с валидным контрольным заданием; отдельно доля завершивших от всех назначенных. Не скрывать отказы и пропуски; отдельно анализ по назначенной группе с чувствительностью к пропускам. Фиксировать медиану времени, сообщения о давлении, оценку релевантности. Повторное тестирование через 7 дней только по согласию; окно условное.
6. Экономика — отдельная последующая гипотеза, не первичная цель. При согласии владельца и наличии агрегированных данных измерить подтверждённые заказы, повторные покупки, вклад когорты за одинаковые периоды и валюты. Не складывать оценки потребностей как выручку; не вычислять LTV без удержания и горизонта. Отказ может быть успешным исходом обучения.
7. Переход к разработке Learning Engine после согласования архитектуры и рубрик; к коммерческой интеграции только после UX/QA и согласования владельца. Никакой публикации.

## Пример рубрики для аудита Андрея
Новый пример: в отчёте указано, что 8/8 UTM сохранились. Вопрос: известно ли число заказов из этих переходов? Ожидается понимание, что сохранение меток не измеряет заказы; для выводов нужны данные аналитики и заказов. Два критерия по 0/1, не оценивать согласие обсуждать пилот. Другой пример: лабораторная скорость не равна измеренной потере продаж.
